## Decision

The promoted default is:

- artifact family: `512x64`
- runtime search config: `8/48/48`

Reason:

- it is the best measured full-stack score on this frontier
- it improves full-stack `p99` materially over the previous `512x32` default
- it keeps detection loss acceptable relative to the latency win

## Rejected promotions

- `10/96/48`:
  - best evaluator-side detection on this family
  - not promoted because it moved the service-side tail too far in the wrong direction
- `10/72/48`:
  - strong detection improvement
  - clearly worse full-stack score than `8/48/48`
- `6/48/48`:
  - nearly identical to `8/48/48`
  - slightly worse measured score, so there is no reason to prefer it

## Immediate implication

The `512x64` family moved the frontier, but it did not solve the core problem:

- search is still the service-side tail bottleneck
- memory headroom still exists
- the next passes should focus on structurally cheaper candidate discovery, cheaper tail scan behavior, or a search algorithm that delivers better recall per scanned vector
